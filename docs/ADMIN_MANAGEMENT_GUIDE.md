# Admin User Management Guide

Quick reference for managing admin users in the GangGreen platform.

## Overview

The GangGreen platform has four user roles:
- **admin**: Full platform access, can manage all resources
- **organization**: Can create and manage initiatives
- **community**: Can participate in local forest activities
- **individual**: Basic user with donation and tree planting capabilities

## Supabase Super Admin vs Database Admin

### Supabase Super Admin
- **Who**: The project owner in Supabase Dashboard
- **Access**: Full control over Supabase project settings, database, storage, auth
- **Location**: Managed in Supabase Dashboard → Settings → Team
- **Purpose**: Infrastructure and platform management

### Database Admin Users
- **Who**: Users with `role = 'admin'` in the `users` table
- **Access**: Application-level admin capabilities (manage initiatives, verify carbon credits, etc.)
- **Location**: Managed through SQL queries in the `users` table
- **Purpose**: Content moderation and platform operations

4. Click **New query**

### 2. Check Current Admins

```sql
SELECT id, email, role, created_at
FROM users
WHERE role = 'admin'
ORDER BY created_at DESC;
```

### 3. Grant Admin Rights

**Single User:**
```sql
UPDATE users 
SET role = 'admin', updated_at = NOW()
WHERE email = 'user@example.com'
RETURNING id, email, role;
```

**Multiple Users:**
```sql
UPDATE users 
SET role = 'admin', updated_at = NOW()
WHERE email IN (
  'admin1@example.com',
  'admin2@example.com',
  'admin3@example.com'
)
RETURNING id, email, role;
```

### 4. Verify the Change

```sql
SELECT id, email, role, updated_at
FROM users
WHERE email = 'user@example.com';
```

## Common Tasks

### Find All Users

```sql
SELECT 
  u.id,
  u.email,
  u.role,
  up.full_name,
  up.organization,
  u.created_at
FROM users u
LEFT JOIN user_profiles up ON u.id = up.id
ORDER BY u.created_at DESC;
```

### Revoke Admin Rights

```sql
UPDATE users 
SET role = 'individual', updated_at = NOW()
WHERE email = 'former-admin@example.com'
RETURNING id, email, role;
```

### Check User Activity

```sql
SELECT 
  u.email,
  u.role,
  COUNT(DISTINCT i.id) as initiatives_created,
  COUNT(DISTINCT t.id) as trees_planted,
  COUNT(DISTINCT nb.id) as nft_badges
FROM users u
LEFT JOIN initiatives i ON u.id = i.organization_id
LEFT JOIN trees t ON u.id = t.planted_by
LEFT JOIN nft_badges nb ON u.id = nb.owner_id
WHERE u.email = 'user@example.com'
GROUP BY u.email, u.role;
```

## Authentication & Access Tokens

### Important Notes

1. **Admin role does NOT affect login**
   - All users login the same way through Supabase Auth
   - Admin role only affects permissions after login

2. **Access Tokens**
   - Generated by Supabase Auth on login
   - Same token format for all user roles
   - Role is checked server-side via RLS policies

3. **Testing Admin Access**
   ```typescript
   // In your application
   const { user } = useAuth();
   
   if (user?.role === 'admin') {
     // Show admin features
   }
   ```

## Security Best Practices

### ✅ DO

- Keep a list of all admin users
- Regularly audit admin access (monthly)
- Use organization emails for admin accounts
- Verify email addresses before granting admin rights
- Document why each user needs admin access
- Revoke admin rights when no longer needed

### ❌ DON'T

- Grant admin rights to personal email accounts
- Share admin credentials
- Leave inactive admin accounts
- Grant admin rights without verification
- Use admin accounts for testing

## Troubleshooting

### User Not Found

**Problem**: `UPDATE` returns 0 rows

**Solutions**:
1. Check if user registered: `SELECT * FROM auth.users WHERE email = 'user@example.com';`
2. Verify email spelling (case-sensitive)
3. User must register through the app first

### User Can't Access Admin Features

**Problem**: User has admin role but can't access admin features

**Solutions**:
1. Verify role in database: `SELECT role FROM users WHERE email = 'user@example.com';`
2. Check if user logged out and back in (token refresh)
3. Verify RLS policies are enabled: `SELECT tablename FROM pg_tables WHERE schemaname = 'public' AND rowsecurity = true;`
4. Check browser console for errors

### Multiple Users Need Admin Rights

**Problem**: Need to promote several users at once

**Solution**: Use bulk update query
```sql
UPDATE users 
SET role = 'admin', updated_at = NOW()
WHERE email IN (
  'user1@example.com',
  'user2@example.com',
  'user3@example.com'
)
RETURNING id, email, role;
```

## Audit Trail

### View Recent Role Changes

```sql
SELECT 
  id,
  email,
  role,
  created_at,
  updated_at,
  CASE 
    WHEN updated_at > created_at + INTERVAL '1 minute' 
    THEN 'Role changed'
    ELSE 'Original role'
  END as status
FROM users
WHERE role = 'admin'
ORDER BY updated_at DESC;
```

### Export Admin List

```sql
COPY (
  SELECT 
    u.email,
    u.role,
    up.full_name,
    up.organization,
    u.created_at,
    u.updated_at
  FROM users u
  LEFT JOIN user_profiles up ON u.id = up.id
  WHERE u.role = 'admin'
  ORDER BY u.created_at
) TO '/tmp/admin_users.csv' WITH CSV HEADER;
```

## Emergency Procedures

### Lost Admin Access

If all admin users are locked out:

1. **Via Supabase Dashboard** (as project owner):
   ```sql
   -- In SQL Editor
   UPDATE users 
   SET role = 'admin'
   WHERE email = 'your-email@example.com';
   ```

2. **Via Supabase CLI**:
   ```bash
   supabase db execute "UPDATE users SET role = 'admin' WHERE email = 'your-email@example.com';"
   ```

### Revoke All Admin Rights (Emergency)

```sql
-- Demote all admins except one
UPDATE users 
SET role = 'individual', updated_at = NOW()
WHERE role = 'admin' 
  AND email != 'keep-this-admin@example.com'
RETURNING id, email, role;
```

## Monitoring

### Daily Checks

```sql
-- Count admins
SELECT COUNT(*) as admin_count 
FROM users 
WHERE role = 'admin';

-- Recent admin activity
SELECT 
  u.email,
  COUNT(DISTINCT i.id) as initiatives_today
FROM users u
LEFT JOIN initiatives i ON u.id = i.organization_id 
  AND i.created_at > CURRENT_DATE
WHERE u.role = 'admin'
GROUP BY u.email;
```

### Weekly Audit

```sql
-- Admin users with no recent activity
SELECT 
  u.email,
  u.role,
  u.updated_at,
  MAX(i.created_at) as last_initiative,
  MAX(t.created_at) as last_tree_planted
FROM users u
LEFT JOIN initiatives i ON u.id = i.organization_id
LEFT JOIN trees t ON u.id = t.planted_by
WHERE u.role = 'admin'
GROUP BY u.email, u.role, u.updated_at
HAVING MAX(i.created_at) < NOW() - INTERVAL '30 days'
   OR MAX(i.created_at) IS NULL;
```
